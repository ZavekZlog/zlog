# Zlog issued PDF — locked design rules

These rules govern every site diary PDF Zlog issues, for every client. Where the code and this file disagree, this file is right and the code is wrong.

## 1. The principle
The report's appearance language is Zlog's, not the client's. A report for one client and a report for another are identical below the header banner, except for two elements: the highlight rule along the top of each container table, and the project name in the cover band. Everything else — greys, whites, grid lines, fonts, sizes, padding, row heights, structure, page frame, footer — is the same in every report.

Superseded: the project name in the cover band is not a brand-colour exception. Below the banner, the only element that takes the client's brand colour is the highlight rule on each container table. The cover name is neutral grey, as section 6 now requires.

## 2. Page frame
A thin rule forms a closed rectangle around every page, including table pages, appendix pages and photo pages. It is a fixed neutral ink colour and never takes the client's brand colour. No table, box or image edge overprints it.

## 3. Header banner
Full width, solid, in the client's brand colour, on every page. Client logo small, top left, faithful to their own artwork; never add or alter taglines or company-form text. Page title centred, semi-bold, not heavy black. Project name and reference in the right-hand slot. Banner depth fixed and identical for every client; the logo scales inside it. No accent bar beneath the banner.

One shared banner component is used by every report type Zlog issues, including the site diary, weekly progress, an H&S inspection, and any later type. The banner is identical on every page of a report, including the cover: the same title, the same case, and the same position. That title is DAILY SITE DIARY. It is centred on the banner's horizontal centre, measured from the title's text block, not from where the text starts. The logo keeps its present size. No page substitutes its own wording, such as "Site records".

## 4. Below the banner
The only element carrying the client's brand colour below the banner is the top highlight rule on each container table. The page frame, section title text, label cell text, photo reference labels, grid lines and footer all take fixed neutral colours. The cover band project name is the exception described in section 6. Where the brand colour is red, the cover name uses the same dark slate as the banner.

Superseded: the cover name is not that exception, and it does not switch to dark slate when the brand is red. The cover name is neutral grey. The red rule in section 12 still applies to the banner, the container rules, and the logo.

## 5. Container tables
Each section is built top to bottom as: a fine rule in the brand colour, full width, closer to a hairline than a bar; then a dove grey title bar with the title in neutral ink, bold, uppercase, left aligned with clear left padding, numbered sequentially through the document; then the table body. The only brand-coloured element on the container is that top rule. Inside: full grid lines on every cell and every row with no missing dividers, in light neutral grey; every row has a complete horizontal rule across the full width, and every cell has a complete border on all four sides; label cells dove grey, data cells white; no alternating row shading; all cell text vertically centred; body text about 9.5pt; clear left padding. A single line of text sits in a compact row with modest padding. Row height is always the content height plus that padding. A row, a section title bar, and a paragraph block size to their content and are never given a fixed height that clips the text. Nothing that follows may overlap them. Rows never stretch to fill a page. A page ending with space below it is correct.

## 6. Cover page
Project name and address in one dove grey band directly beneath the banner, centred, no white gap, a subtle hairline along its bottom edge, the page frame running unbroken down its sides. The name is brand-coloured bold; the address beneath it is neutral. Where the brand colour is red, the name uses the same dark slate as the banner. The report date is a row in the cover table, not in the band. No second grey band beneath it. The cover photograph sits on the page with no frame or outline. The cover table follows the same design as every other table.

Superseded: "The name is brand-coloured bold" and "Where the brand colour is red, the name uses the same dark slate as the banner." The project name in the cover band is neutral grey. The address beneath it stays neutral.

## 7. Section order
After the cover page, the issued PDF uses this order. A section appears only when it has content. An empty section is omitted entirely, with no heading and no empty table.

1. Site summary
2. Labour
3. Equipment on hire
4. Site attendance
5. Visitors
6. Permits to work
7. Deliveries
8. Temporary works & scaffolding checks
9. Work area records
10. Attendance register
11. Photographs
12. Declaration & signature

No Document Control block.

Superseded: the numbered list above, the sentence that a section appears only when it has content, and the sentence that an empty section is omitted. The issued order after the cover page is fixed:

1. Attendance
2. Visitors
3. Works
4. Hazards
5. Permits
6. Attendance register
7. Daily Site Checks
8. Site Records
9. Work Photographs
10. Supporting Documents
11. Declaration & Signature

Daily Site Checks and Site Records are not conditional. Both are present in every diary. A blank answer is never printed as "No" or "none".

Daily Site Checks are always ticked, and the five lines are always these: final site inspection before closing site, no issues; welfare facilities clean and tidy; stored materials safe and secure; fire alarm confirmed reactivated by security; no H&S incidents / observations.

Site Records always shows the yes/no selectors: Variations, Plant on site, Temporary works, Delays or issues, Actions required. Plant on site and Temporary works open a detail table only when the stored answer is Yes. RFIs list only those newly raised that day.

Work Photographs is one section. Each work area is a sub-heading under it. Areas flow on in the page stream. Starting an area does not start a new page.

Supporting Documents follows Work Photographs. Permits to work, toolbox talks, and MEWP or other inspection sheets sit there, not among the work photographs. The rotation spec states that section's frame, numbering, and caption. Supporting Documents is omitted when it has nothing to show. That omission is not inferred as "none".

Declaration & Signature is last.

## 8. Photographs
Work photographs are documentary evidence and the most important content in the report. Four per page in a two by two grid, all frames identical, frames portrait. The grid fills the page with minimal margins and no wide gutters. Correcting a photograph's stored orientation so it displays the right way up is required. A landscape photograph is then rotated 90 degrees to fill its portrait frame. Photographs are never cropped. All frames stay identical in size. Each photo has a caption area of fixed height beneath it so frames stay identical with or without a caption. Only the last photo page may end short.

Superseded where it conflicts with the following:

The outline sits snug around the photograph. There is no white inside the outline. The photograph is shown whole and is never cropped. An older rule that kept one fixed frame and left white beside the photograph is superseded.

The photo number and every reference text sit in the caption bar. Nothing in this section places the number at the top left of the photograph.

The photo grid is top-aligned at the normal content start. It is never centred vertically. A short page leaves its spare space below the grid. "Only the last photo page may end short" is superseded where it was read as a reason to centre a short grid or to push an area onto its own page.

The section heading is "Work Photographs", as section 7 requires. Area sub-headings follow it, and areas flow on without each area starting a new page.

The Work Photographs heading stays the same height and style as every other section bar: 36.65pt. It is not a separate photo heading.

The area sub-heading is one slim style of about 20pt, used for every area. It does not change with where the area sits on the page. The sub-heading spans the full width, and that area's photographs start on the next row. A part-filled row stays part-filled. The sub-heading stays with at least the first row of its photographs and is never left alone at the foot of a page.

Photo numbering continues across areas.

All frames of one photos-per-page setting are one uniform size on every page. The size is derived from the content height so that the Work Photographs bar, one area sub-heading, and two full rows fit on one page. The clearance is the existing 14pt photo-page slack: a 2pt remainder drops the second row onto the next page. The image and frame figures are not hard-coded.

Supporting Documents use that same frame size, the same grid, and the same snug outline. Numbering restarts at 1 in that section. Each caption is the document name followed by ": hard copy in site file".

## 9. Appendices and attendance register
Appendices come before the work photographs. The register shows the full top of the sheet with all names, never cropped to one day's rows. It is embedded at source resolution and fills a full page. Its heading, caption and image stay together on one page; if they do not fit, the whole block moves to the next page. Appended scans carry the caption "Legal document - reproduced untouched."

## 10. Declaration & signature
One full-width table, identical in every report, never reshaped to fit around photographs. The section is titled "Declaration & signature". Author name, position or role, and date as rows. The signature image aligns with that block rather than floating at a different height, sized in proportion rather than dominating. The declaration wraps as one paragraph across the full width. Declaration & signature is last and flows straight on after the final photograph, wherever it lands, leaving space below if that is how it falls.

Superseded: Declaration & signature follows Supporting Documents when that section has content. Supporting Documents is omitted when it has nothing to show, and Declaration & Signature then follows the final work photograph. The title of the section is "Declaration & Signature".

## 11. Footer
Every page: one composite string on the left and the page line on the right, with nothing centred. The left string is the project reference, the document title "Daily Site Diary", and the report date, separated by middots. The right string is "Produced with Zlog · Page x of y". "Produced with Zlog" is a link only when ZLOG_LANDING_URL is a real address. While that constant is the placeholder TODO, those words are plain text and are not a link. The line sits above a thin rule.

## 12. The red exception
Red means hazard on site. Where the brand colour is red: the banner becomes dark slate, the container top rules become charcoal, and the client's red appears in their logo only. Applied automatically from the brand colour.

## 13. Provenance
The labour table carries a source line beside its heading, small, italic, grey, right aligned: "Source: site attendance register, scanned" where a register is attached, or "Source: entered manually" where it is not.

## 14. Verification
A change to the issued PDF is not verified until it has been checked on a real diary, generated through the worker, exactly as the app produces it. A render from source with invented sample data proves nothing: it uses different content, different wrapping and possibly a different font.

To verify: generate the PDF for a real report through the worker, extract the text of the affected pages, and confirm nothing is truncated. Never report a PDF fault fixed on the strength of a sample render.
