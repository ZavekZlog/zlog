# Zlog issued PDF — locked design rules

These rules govern every site diary PDF Zlog issues, for every client. Where the code and this file disagree, this file is right and the code is wrong.

## 1. The principle
The report's appearance language is Zlog's, not the client's. A report for one client and a report for another are identical below the header banner, except for two elements: the highlight rule along the top of each container table, and the project name in the cover band. Everything else — greys, whites, grid lines, fonts, sizes, padding, row heights, structure, page frame, footer — is the same in every report.

Superseded: the project name in the cover band is not a brand-colour exception. Below the banner, the only element that takes the client's brand colour is the highlight rule on each container table. The cover name is neutral grey, as section 6 now requires.

## 2. Page frame
A thin rule forms a closed rectangle around every page, including table pages, appendix pages and photo pages. It is a fixed neutral ink colour and never takes the client's brand colour. No table, box or image edge overprints it.

## 3. Header banner
Full width, solid, on every page. When a reporting company colour has been sampled, the fill is that colour exactly, whatever it is: any hue, silver, pink, yellow, white, or grey. A sampled colour is never replaced, including when the sample itself is white, silver, or grey.

When no company branding has been chosen at all — nothing uploaded, and no saved brand selected — the banner uses one default neutral grey, `#6E6E6E`. That default is used only in that case. Its red, green and blue values are 110, 110 and 110, so it is a true neutral. It is clearly darker than the dove-grey band under the banner, `#E4E2DE`. White wording on `#6E6E6E` contrasts at 5.10:1. On Project Details, under the Reporting Company heading, the diary screen shows two display lines when no branding is set: "No branding selected: default grey applied" and "Upload your company logo to use your colour." Those lines are not the company name and are never saved. They are not printed on the PDF.

The words on the banner — DAILY SITE DIARY, the project name, and the reference — stay legible. Their colour is white or the document ink, chosen from the banner colour's lightness, as section 12 states. The logo is not part of that choice. The logo stays the company's own artwork. It is not altered, recoloured, or given anything extra. It sits small, top left, and scales inside the fixed banner depth. If that artwork would not be legible on the banner, nothing is invented in its place. Page title centred. Project name and reference in the right-hand slot. Banner depth fixed and identical for every company. No accent bar beneath the banner.

One shared banner component is used by every report type Zlog issues, including the site diary, weekly progress, an H&S inspection, and any later type. The banner is identical on every page of a report, including the cover: the same title, the same case, and the same position. That title is DAILY SITE DIARY. It is centred on the banner's horizontal centre, measured from the title's text block, not from where the text starts. The logo keeps its present size. No page substitutes its own wording, such as "Site records".

When a reporting company colour has been sampled, that sampled colour is the banner fill on every page. That includes supporting-document pages, attendance-register pages, and photograph pages. Those pages do not drop the sampled colour or paint a different one.

Superseded: "There is no default banner colour and no fallback banner colour. Grey is used only when the company's own branding is grey." A default grey now exists, and only for the case where no branding has been chosen. A sampled grey is still used as sampled. Superseded: "in the client's brand colour", where that meant the end client or a dark-slate stand-in for red. Superseded: a dark-slate banner, a restrained accent rewrite of a sampled colour, and the blue-grey `#4B5563` painted in place of a sampled white, silver, or pale colour. Superseded: "If the company has supplied a light or white logo, that is the logo used on a red banner." A second logo is not invented.

## 4. Below the banner
A report's colours are sampled only from the reporting company, the company producing the report, such as CBRE or Milestone. They are never sampled from the end client the work is for.

The only element that may carry the reporting company's brand colour below the banner is the top highlight rule on each container table, and only when section 12 allows it. When it is allowed, that line is the sampled colour exactly. It is not lightened, darkened, or moved in saturation, because a company may object to its colour being altered. A red banner does not licence red below it. A pale banner does not licence a pale top line on white. When no branding has been chosen, no brand colour exists, so those top lines use the light pigeon grey. The page frame, section title text, label cell text, photo reference labels, grid lines and footer all take fixed neutral colours. The cover name is neutral grey.

Superseded: "the client's brand colour", where that was read as the end client's colour, and "Where the brand colour is red, the cover name uses the same dark slate as the banner." The cover name does not switch to dark slate. Grid lines are not a brand colour. Superseded: "only when the brand is not red-dominant", where that was the only case that replaced the top rule. Section 12 also replaces it when the brand colour is too light to show on white, and when no branding has been chosen. Superseded: a top line that rewrites the sampled colour, holding saturation between 0.25 and 0.72 and lightness between 0.28 and 0.52, or replacing a near-monochrome sample with `#4B5563`.

## 5. Container tables
Each section is built top to bottom as: a fine rule in the brand colour, full width, closer to a hairline than a bar; then a dove grey title bar with the title in neutral ink, bold, uppercase, left aligned with clear left padding, numbered sequentially through the document; then the table body. The only brand-coloured element on the container is that top rule. Inside: full grid lines on every cell and every row with no missing dividers; every row has a complete horizontal rule across the full width; label cells dove grey, data cells white; no alternating row shading; all cell text vertically centred; body text about 9.5pt; clear left padding. A single line of text sits in a compact row with modest padding. Row height is always the content height plus that padding. A row, a section title bar, and a paragraph block size to their content and are never given a fixed height that clips the text. Nothing that follows may overlap them. Rows never stretch to fill a page. A page ending with space below it is correct.

Superseded: "in light neutral grey" and "every cell has a complete border on all four sides" where each cell drew its own four borders. Also superseded: the grid colour `#73807a`, and the older bluish `#C3CFDA`. A grid line between cells is one fixed light neutral grey for every reporting company: `#C6C7C8`. Its red, green and blue values are 198, 199 and 200, within 2 of each other, so it carries no blue tint and no green tint. `#C4C7CA` is the lightness aimed at; it is not the issued colour, because its channels are 6 apart. The stroke weight stays the Mansfield weight, 0.8pt, drawn once per shared edge. The Mansfield header also carries a 2.2pt brand line on top of the title bar; Zlog keeps the hairline already stated above.

The top rule on each table, and each section's top rule, is the reporting company's brand colour. When section 12 withholds that colour, the line is dove grey.

Every container is a header bar plus a bordered body. The body starts on the bar's bottom edge, with no gap. A text-only body — the declaration paragraph, an attendance-register caption, and any similar block — sits inside that same perimeter, with the same left padding as the table cells. Measured on the Mansfield reference, that left padding is 9.7pt. No text sits unbordered under a header.

Superseded: "A text-only body — Site Summary", where Site Summary meant one prose block under one header. Site Summary is the subject boxes in the Summary section. Each of those boxes is still a header bar plus a bordered body, with that same 9.7pt left padding.

## 6. Cover page
Project name and address in one dove grey band directly beneath the banner, centred, no white gap, a subtle hairline along its bottom edge, the page frame running unbroken down its sides. The name is brand-coloured bold; the address beneath it is neutral. Where the brand colour is red, the name uses the same dark slate as the banner. The report date is a row in the cover table, not in the band. No second grey band beneath it. The cover photograph sits on the page with no frame or outline. The cover table follows the same design as every other table.

Superseded: "The name is brand-coloured bold" and "Where the brand colour is red, the name uses the same dark slate as the banner." The project name in the cover band is neutral grey. The address beneath it stays neutral.

After the cover page, the issued PDF uses this order. A section appears only when it has content. An empty section is omitted entirely, with no heading and no empty table.

4. Site attendance
5. Visitors
6. Permits to work
7. Deliveries
8. Temporary works & scaffolding checks
9. Work area records
10. Attendance register
11. Photographs
12. Declaration & signature

No Document Control block.

Superseded: the numbered list above, the sentence that a section appears only when it has content, and the sentence that an empty section is omitted. The issued order after the cover page is fixed. Summary is first, which is where the issued PDF places it. The other sections keep this order:

1. Summary
2. Attendance
3. Visitors
4. Works
5. Hazards
6. Permits
7. Attendance register
8. Daily Site Checks
9. Site Records
10. Work Photographs
11. Supporting Documents
12. Declaration & Signature

Superseded: the numbered list above, and the sentence that the other sections keep that order. That list placed Work Photographs before Supporting Documents. Superseded: the issued order that began at Attendance and had no Summary line.

After the cover page, the issued order is:

1. Summary
2. Attendance
3. Visitors
4. Works
5. Hazards
6. Permits (the table of permit rows)
7. Attendance Register
8. Daily Site Checks
9. Site Records
10. Supporting Documents
11. Site Evidence Photos
12. Declaration & Signature

The attendance register and Supporting Documents both come before the photographs. Declaration & Signature stays last.

Daily Site Checks and Site Records are not conditional. Both are present in every diary. A blank answer is never printed as "No" or "none".

Daily Site Checks are always ticked, and the five lines are always these: final site inspection before closing site, no issues; welfare facilities clean and tidy; stored materials safe and secure; fire alarm confirmed reactivated by security; no H&S incidents / observations.

Site Records always shows the yes/no selectors: Variations, Plant on site, Temporary works, Delays or issues, Actions required. Plant on site and Temporary works open a detail table only when the stored answer is Yes. RFIs list only those newly raised that day.

Site Evidence Photos is one section. It holds only actual site work photographs. Each work area is a sub-heading under it. Areas flow on in the page stream. Starting an area does not start a new page.

Supporting Documents comes before Site Evidence Photos. Permit to work photographs, toolbox talks, and MEWP or other inspection sheets all live there, never in the site evidence photos. The section is omitted when it has nothing to show. That omission is not inferred as "none". The user chooses 1, 2, 4 or 6 documents on a page, set once for the diary. The default is 4. Section 8 states the frame and the caption.

Superseded: "Work Photographs is one section." The issued name is "Site Evidence Photos". Superseded: "Supporting Documents follows Work Photographs."

Declaration & Signature is last.

## Summary
The Summary is not one block of prose. It is structured subject boxes. Each box is a grey label header bar, the same style as every other container, over a bordered body. The body has the same 9.7pt left padding. The body is brief description text only.

1. "Site works achieved today" is a full-width lead box, and it is always first when that text exists.
2. The next boxes sit two across the page: "Deliveries", then "Delays and issues". If a third box is present, "Welfare" goes full width below them. An odd box out is always full width. `daily_reports.delays_issues` feeds the "Delays and issues" box.
3. A box with no content is omitted from the PDF entirely. A blank box is never printed as "None", "No", or "N/A". Nothing is inferred from a blank.
4. A legacy diary is one where the three subject fields are empty. Prose in `site_summary` then renders as a single full-width box titled "Summary". When that prose and `delays_issues` both have text, the PDF prints a full-width "Summary" box, then a full-width "Delays and issues" box. When any of the three subject fields has text, those subject boxes are used and the legacy prose box is not printed.
5. The grid line weight and colours, the banner, the footer, and the brand colour rules are the same as the rest of the document. No new colours. Red stays in the banner only.
6. Summary stays in the fixed page order above. No other section moves.

## 8. Site Evidence Photos
Site evidence photos are documentary evidence and the most important content in the report. This section holds only actual site work photographs. Permit to work photographs, toolbox talks, and MEWP or other inspection sheets do not sit here.

The count is chosen for each work area: 1, 2, 4 or 6 photographs on a page. The default is 4. The stored values are full for 1, grid2 for 2, grid4 for 4, and grid6 for 6.

The photo box is portrait, three wide by four high. The issued sizes, in points, are: 1 per page (full) 403.18 by 537.57; 2 per page (grid2) 251.44 by 335.25; 4 per page (grid4) 199.52 by 266.03; 6 per page (grid6) 165.56 by 220.75. Every photograph that uses a given count uses that box. The grid fills the page with minimal margins and no wide gutters. Correcting a photograph's stored orientation so it displays the right way up is required. A landscape photograph is turned to stand in the portrait box. The photograph is shown whole. Nothing is ever cropped. Each photo has a caption area of fixed height beneath it so the boxes stay aligned with or without a caption.

Superseded: "Four per page in a two by two grid" as the only count. Superseded: "A landscape photograph is then rotated 90 degrees to fill its portrait frame", where "fill" was read as a crop. Superseded: "All frames stay identical in size" as one size for the whole section. Superseded: "The outline sits snug around the photograph. There is no white inside the outline", where that was read as a reason to crop the photograph or to abandon these boxes. The box is the size for the count. The photograph inside it is never cropped. An older rule that kept one fixed frame and left white beside the photograph is not brought back as a reason to crop.

The photo number and every reference text sit in the caption bar. Nothing in this section places the number at the top left of the photograph.

The photo grid is top-aligned at the normal content start. It is never centred vertically. A short page leaves its spare space below the grid. "Only the last photo page may end short" is superseded where it was read as a reason to centre a short grid or to push an area onto its own page.

The section heading is "Site Evidence Photos", as section 7 requires. Area sub-headings follow it, and areas flow on without each area starting a new page.

The Site Evidence Photos heading stays the same height and style as every other section bar: 36.65pt. It is not a separate photo heading.

The area sub-heading is one slim style of about 20pt, used for every area. It does not change with where the area sits on the page. The sub-heading spans the full width, and that area's photographs start on the next row. A part-filled row stays part-filled. The sub-heading stays with at least the first row of its photographs and is never left alone at the foot of a page.

Photo numbering continues across areas.

Superseded: "All frames of one photos-per-page setting are one uniform size on every page. The size is derived from the content height so that the Work Photographs bar, one area sub-heading, and two full rows fit on one page. The clearance is the existing 14pt photo-page slack: a 2pt remainder drops the second row onto the next page. The image and frame figures are not hard-coded." The issued photo boxes are the four sizes stated above.

Each site evidence photo has a button that pulls it out of the area's normal grid, for greater detail. The user chooses 1 per page or 2 per page for that photo. A photo flagged 1 per page takes a page of its own, using the 1-per-page box. A photo flagged 2 per page pairs with the next photo flagged 2 per page, in order. The pair uses the 2-per-page box. If there is no partner, that photo is shown 1 per page instead. A flagged page keeps the photo's place in the order. The grid pages carry on around the flagged pages. Every photo that is not flagged keeps the frame of its work area.

Supporting Documents uses those same boxes. The count is 1, 2, 4 or 6, set once for the diary, and the default is 4. Numbering restarts at 1 in that section. Each caption is the document name followed by ": hard copy in site file".

Superseded: "Supporting Documents use that same frame size, the same grid, and the same snug outline", where that meant whatever frame the work photographs were using. Supporting Documents has its own count, chosen once for the diary, and uses the matching box from the sizes above.

## 9. Appendices and attendance register
Appendices come before the site evidence photos. The attendance register comes before Site Evidence Photos. Supporting Documents also comes before Site Evidence Photos. The register shows the full top of the sheet with all names, never cropped to one day's rows. It is embedded at source resolution and fills a full page. Its heading, caption and image stay together on one page; if they do not fit, the whole block moves to the next page. Appended scans carry the caption "Legal document - reproduced untouched."

## 10. Declaration & signature
One full-width table, identical in every report, never reshaped to fit around photographs. The section is titled "Declaration & signature". The declaration wraps as one paragraph across the full width. Declaration & signature is last and flows straight on after the final site evidence photograph, wherever it lands, leaving space below if that is how it falls. Supporting Documents sits before the photographs, so the declaration does not follow that section.

Superseded: "Author name, position or role, and date as rows. The signature image aligns with that block rather than floating at a different height." Measured on `reference-mansfield.pdf`, the sign-off is a header bar, then one bordered paragraph flush under it, then one table flush under the paragraph. Declaration & Signature is that one table. Author Name, Position / Role, Date and Signature are consecutive rows of the same table: the same full width, the same label column, the same borders, and no gap between rows. The signature image sits inside the value cell of the Signature row. The declaration paragraph is the bordered text body directly under the header, inside the same perimeter as those rows. The table is not reshaped around photographs.

Superseded: Declaration & signature follows Supporting Documents when that section has content. Supporting Documents is omitted when it has nothing to show, and Declaration & Signature then follows the final work photograph. The title of the section is "Declaration & Signature".

## 11. Footer
Every page: one composite string on the left and the page line on the right, with nothing centred. The left string is the project reference, the document title "Daily Site Diary", and the report date, separated by middots. The right string is "Produced with Zlog · Page x of y". "Produced with Zlog" is a link only when ZLOG_LANDING_URL is a real address. While that constant is the placeholder TODO, those words are plain text and are not a link. The line sits above a thin rule.

## 12. The red exception
Red means hazard on site. A brand is red-dominant by the existing `isPdfBrandRed` test, and by no other test: the hue sits within 15 degrees of red (0–15 or 345–360), saturation is at least 0.28, and lightness is between 0.12 and 0.72. Orange is outside that band. The test is applied to the reporting company's colour.

The header banner is that colour exactly as sampled whenever a colour has been sampled, including white, silver, and grey. The default neutral grey `#6E6E6E` is used only when no branding has been chosen at all. It is not a substitute for a sampled colour.

The words on the banner use white `#FFFFFF` when the banner colour's relative luminance is 0.179 or below, and the document ink `#1C2126` when it is above 0.179. At 0.179, dark ink contrasts more strongly with the banner than white does. The measure is the existing `relativeLuminance` helper. On the default grey, luminance is 0.156, so the wording is white, at 5.10:1. The logo artwork is not recolored to follow that choice.

Below the banner, a red-dominant brand never colours a table top line, a section rule, a title bar, or text. Those top lines also stay the existing dove grey, `#E4E2DE`, when the sampled colour is too light to show as a line on white, and when no branding has been chosen. Too light means `relativeLuminance` above 0.30. Above that, the line falls below 3:1 contrast on white. White, silver, and pale yellow are above it. A sampled colour that is not red-dominant and is not above 0.30 is painted exactly as sampled. Nothing adjusts its saturation or lightness. Red appears only in the header banner area: the banner fill, and the logo inside it. Nowhere else in the report. No table rule, title bar, section rule, text, icon, badge or photo label takes red, a red tint, charcoal, or a darker step of red.

Superseded: "A missing or unreadable colour leaves the banner unfilled. It does not become grey." No branding now uses `#6E6E6E`. Superseded: "The header banner is coloured as it is today. A red-dominant brand still paints that banner in dark slate." Superseded: "Brands that are not red are unchanged." Superseded: "the container top rules become charcoal, and the client's red appears in their logo only." Charcoal is not used. Red below the banner is not used. Superseded: "A sampled colour that is not red-dominant and is not above 0.30 keeps the existing top-line colour", where that existing colour was the restrained accent rewrite.

## 13. Provenance
The labour table carries a source line beside its heading, small, italic, grey, right aligned: "Source: site attendance register, scanned" where a register is attached, or "Source: entered manually" where it is not.

## 14. Verification
A change to the issued PDF is not verified until it has been checked on a real diary, generated through the worker, exactly as the app produces it. A render from source with invented sample data proves nothing: it uses different content, different wrapping and possibly a different font.

To verify: generate the PDF for a real report through the worker, extract the text of the affected pages, and confirm nothing is truncated. Never report a PDF fault fixed on the strength of a sample render.
